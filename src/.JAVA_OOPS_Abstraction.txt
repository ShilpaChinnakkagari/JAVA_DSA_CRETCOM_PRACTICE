I. ABSTRACTION :
==================
    Abstraction in Java is the process of hiding internal implementation details (unnecessary implementation)
    and showing only essential functionality to the user, It hides the complex details.
    ==> It focuses on what an object does rather than how it does it.
    ==> Abstract classes may have methods without implementation and must be implemented by subclasses (by overriding
     in child classes) .By abstracting functionality, changes in the implementation do not affect the code that depends
     on the abstraction.

    Example : We are driving the car, we are aware of how to drive the car but not internal working of engine, fuel injection,
              electronic work internally.

              What you see      → Steering, Brake, Accelerator
              What is hidden    → Engine, Gearbox, Internal Mechanism

IV. ABSTRACT CLASS
===================
    --> abstract class , if a class is declared by 'abstract' keyword and allows both
        (concrete methods) + ( abstract methods )
    --> If a class contains at least one abstract method, the class must be declared as abstract.
    --> can have 0 or more abstract methods.

    Syntax :
    -----------
        abstract <className> {
                // concrete methods
                // abstract methods
        }

        * concrete methods : the methods which are provided with the complete functionality of its
                             implementation.

                             Ex: int add(int a, int b){
                                        return a + b;
                                  }
        * abstract methods : The method which has significant declaration but no implementation.
                             ==> All abstract methods are declared by using abstract keyword.

                             Syntax : abstract <returnType> <MethodName>(<parameters>);

VI. RULES THAT ABSTRACT CLASS FOLLOWS :
=========================================
1. For abstract class, we cannot create object.
   As a part, we cannot invoke the constructor directly.

   WHY ?
   ---> We cannot create an object of an abstract class because it may contain abstract methods without implementation,
        making it an incomplete class. Since objects cannot be created, its constructor cannot be invoked directly.
        However, the constructor of an abstract class is executed when a subclass object is created.

2. The constructor of an abstract class can be called through a child class, either implicitly or explicitly.

    HOW ?
    -----> (implicitly)
    abstract class Vehicle {
               Vehicle() {
                   System.out.println("Vehicle Constructor");
               }
           }

           class Car extends Vehicle {
           }

           public class Test {
               public static void main(String[] args) {
                   Car c = new Car();
               }
           }

           Output : Vehicle Constructor

            Car()
              ↓
            super()   ← inserted automatically by Java
              ↓
            Vehicle()


    -----> (explicitly)
        * If we want to call abstract parent class constructor in child class, we need to use super keyword within
            the child class constructor.

    abstract class Vehicle {
        Vehicle() {
            System.out.println("Vehicle Constructor");
        }
    }

    class Car extends Vehicle {
        Car() {
            super();    // explicit u call
        }
    }
     public class Test {
          public static void main(String[] args) {
             Car c = new Car();
          }
     }
3. We need to override the abstract method in sub class by declaring it as public.
   why?
   ----->
   because interface methods are implicitly public abstract. While overriding, the access level cannot be reduced,
    so the implementing method must also be public.

        Interface Method
               ↓
        public abstract

        Override
               ↓
        must remain public

VIII. INTERFACE :
=================
    ==> It is a java type of definition which is declared by 'interface' keyword.
    ==> act like a logical entity/ blue print to implement the class
        (An entity that exists as a concept or idea in software, but does not physically exist.)
    ==> Interface is a medium between two systems where one system act as a client and another system, which is
        object act as a service.
    ==> Class has to provide the implementation for abstract methods defined in the interface by being implemented
        by the interface.
    ==> To build IS-A-REALTIONSHIP between interface and class, use 'implement' keyword.
    ==> syntax : interface <interfaceName>{
                    // abstract methods
                  }

    Key Rules to Remember
    ---------------------
    1. Class cannot implement interface.
    2. Interface implements the class.
    3. Any variables in interface defined are automatically : public, static, final ( constants).
       why?
       public - to be accessible anywhere, if not, how can the child class override.
       static - belong to the class, as we cannot create object with interface.
       final - value cannot be changed, ensuring constants remain fixed.
    4. Interfaces allow only abstract methods, which are public , abstract by default.
    5. A class implementing an interface must provide implementation
       for all abstract methods, otherwise the class must be declared abstract.
    6. If multiple interfaces contain the same abstract method, only one implementation is required.


    IS-A-RELATIONSHIP         Class                 Interface
    (--------> )
        Class               extends                 not possible
       Interface           implements                 extends


    Why interface cannot allow object creation?
    -------------------------------------------
    An interface cannot be instantiated because it contains abstract behavior and does not provide complete
    implementation. Since it is an incomplete blueprint, Java does not allow object creation for interfaces
    ==> As a part it is static.

    Interface
        | (logical instructions)
      Class
        | (Logical entity)
      Object

2. Functional interface :

*** Why multiple inheritance is possible through interfaces but not through classes?
    -->Java does not support multiple inheritance through classes to avoid the Diamond Problem and ambiguity.
    -->Interfaces support multiple inheritance because they provide only method declarations, and the implementing
        class supplies the actual implementation.

        Classes    → Implementation → Ambiguity

        Interfaces → Declaration   → No Ambiguity

*** What is the Diamond Problem?
    The Diamond Problem is an ambiguity that occurs in multiple inheritance when a class inherits
    from two parent classes that both inherit from the same grandparent class.

    ==> The Diamond Problem is a well-known issue in programming languages that support multiple inheritance, where a class
        inherits the same method from more than one parent class, creating ambiguity about which method should be executed.
                       A
                      / \
                     B   C
                      \ /
                       D
       // class
       class A {
           void show() {
               System.out.println("A");
           }
       }

       class B extends A { }

       class C extends A { }

       // Assume Java allowed this
       class D extends B, C { }

       //interface
       interface A {
           void show();
       }

       interface B {
           void show();
       }

       class C implements A, B {
           public void show() {
               System.out.println("Hello");
           }
       }

    Why Java Avoids the Diamond Problem ?
    -------------------------------------
    Java avoids the Diamond Problem because it creates ambiguity when a child class inherits the same
    method from multiple parent classes. To keep method resolution simple and unambiguous,
    Java does not support multiple inheritance through classes

    How can we achieve diamond problem via interfaces ?
    ----------------------------------------------------
    A diamond-shaped inheritance structure can be created using interfaces. If multiple interfaces provide the
    same default method, ambiguity occurs. Java resolves this by forcing the implementing class to override the
    method and explicitly choose which implementation to use.

    Classes + Diamond  → Not Allowed ❌

    Interfaces + Diamond → Allowed ✅
    because Java forces the class to resolve any ambiguity by overriding in child classes.

    ==> If multiple interfaces contain the same default method, the implementing class must override it
        to resolve ambiguity

        Ex:
        interface A {
            default void sleep() {
                System.out.println("Sleep");
            }
        }

        interface B {
            default void sleep() {
                System.out.println("Sleep not");
            }
        }
